# 개인용 NAS 웹앱 설계

작성일: 2026-11-04
상태: 사용자 승인, 구현 완료 (2026-11-05)

## 목적과 합의된 전제

Docker로 실행하고 PC·휴대폰 브라우저에서 사용하는 개인용 파일 저장소를 만든다.
파일 저장·업로드·다운로드, 파일·폴더 관리, 자주 사용하는 파일의 미리보기를 제공한다.
집에서는 내부망으로 접속하고, 외부에서는 라우터 VPN을 통해 같은 서비스에 접속한다.
개인 계정 로그인을 제공한다. 라우터 재구성과 VPN 설정은 이번 개발 범위에서 제외한다.

## 검토한 접근 방식

1. 단일 앱 컨테이너: 웹 화면과 API를 함께 제공한다. 실행·백업·업데이트가 단순하다.
   독립적인 서비스 확장에는 덜 유연하지만 개인용에 적합하다.
2. 화면과 API를 별도 컨테이너로 구성: 각각 배포·확장하기 좋지만 실행과 관리가 복잡해진다.

사용자는 1번을 선택했다. 아래 기술과 세부 동작은 구현을 위한 제안이며 아직 사용자 확정 사항은 아니다.

## 제안하는 기술 구성

- React와 TypeScript로 반응형 웹 화면을 만든다.
- Python FastAPI가 파일 API, 로그인, 빌드한 웹 화면을 함께 제공한다.
- SQLite에 단일 사용자 계정과 세션을 저장한다. 파일 목록은 실제 저장 폴더를 기준으로 읽는다.
- Docker Compose로 앱 하나를 실행한다. 배포에 Node.js 실행 서버는 필요 없다.
- 의존성 버전은 구현 시 호환되는 지원 버전으로 정하고 잠금 파일로 고정한다.
- 외부 CDN, 온라인 문서 변환 서비스, 외부 계정 연동에 의존하지 않는다.

## 저장소와 데이터 유지

- 호스트의 파일 저장 폴더를 컨테이너의 `/data/files`에 연결한다.
- 계정·세션 DB는 별도 영속 폴더 `/data/app`에 저장한다.
- 임시 업로드는 파일 저장소와 같은 파일시스템의 전용 내부 폴더에 저장한다.
- 컨테이너 교체와 재시작으로 원본 파일이나 계정이 지워지지 않게 한다.
- DB에 파일 원본을 저장하지 않는다. 원본은 일반 파일·폴더로 유지한다.
- 백업은 파일 저장 폴더와 앱 데이터 폴더를 대상으로 하며, DB 백업 시에는 앱 정지를 기본 안내로 한다.
- RAID, 디스크 관리, 자동 백업, 다른 장치와의 자동 동기화는 이번 범위에서 제외한다.

## 파일·폴더 기능

- 현재 폴더 목록, 상위 경로 이동, 이름·크기·수정일 표시, 정렬과 현재 폴더 이름 검색을 제공한다.
- 여러 파일 업로드, 파일 다운로드, 폴더 생성, 파일·폴더 이름 변경·이동·삭제를 제공한다.
- PC에서는 드래그앤드롭을, 휴대폰에서는 파일 선택기를 지원한다.
- 업로드는 파일을 메모리에 통째로 올리지 않고 스트리밍한다. 진행률과 실패 상태를 표시한다.
- 파일별 업로드 크기 상한은 환경변수로 조정하며 기본값은 10 GiB로 제안한다.
- 업로드 완료 시 최종 위치에 반영한다. 중단·실패 시 임시 파일을 정리한다.
- 같은 이름의 파일은 자동 덮어쓰지 않고 충돌을 표시한다. 이름 변경이나 다른 위치 선택으로 해결한다.
- 이동은 저장소 내부에서만 지원한다. 폴더를 자기 자신이나 하위 폴더로 옮기지 못하게 한다.
- 삭제는 확인 후 영구 삭제한다. 휴지통과 복원 기능은 첫 버전에서 제외하며 화면에 이를 명시한다.
- 폴더 통째 다운로드, 폴더 업로드, 이어받기 업로드, 공유 링크는 첫 버전에서 제외한다.

## 형식별 뷰어

| 형식 | 제공 동작 | 범위와 제한 |
| --- | --- | --- |
| PDF | 앱 내부에서 페이지 보기·확대·이동 | PDF.js를 로컬 번들로 제공 |
| DOCX | 문서 내용을 읽는 미리보기 | Mammoth로 변환하고 HTML을 정화하며, 원본의 정확한 페이지·레이아웃 재현은 보장하지 않음 |
| PY, CPP, H, JS, TS, JSON, MD, TXT 등 | 줄 번호와 구문 강조가 있는 텍스트 보기 | 실행·편집하지 않으며 HTML·Markdown도 기본적으로 텍스트로 표시 |
| JPG, JPEG, PNG, GIF, WEBP | 이미지 보기·화면 맞춤 | 브라우저 지원 형식 기준 |
| MP4, WEBM | 브라우저 동영상 플레이어 | HTTP Range를 지원하며 코덱 변환은 제공하지 않음 |
| MP3, WAV, OGG | 브라우저 오디오 플레이어 | 브라우저 지원 코덱 기준 |
| 그 외 | 파일 정보와 다운로드 | 미리보기 불가 안내 |

- 뷰어에도 로그인 확인을 적용하고 파일 URL에 비밀번호나 세션 토큰을 넣지 않는다.
- 파일은 원본 바이트를 유지한다. DOCX 미리보기는 요청 시 생성하며 원본을 수정하지 않는다.
- DOCX는 압축 해제 크기·항목 수·변환 시간 상한을 둔다. 외부 리소스를 가져오지 않는다.
- 텍스트는 미리보기 크기를 제한하고, 초과하거나 디코딩이 불가능하면 다운로드를 안내한다.
- 손상·암호화된 문서와 지원되지 않는 미디어는 오류 안내와 원본 다운로드를 제공한다.

## 계정과 기본 보호

- 단일 소유자 계정만 지원하며 공개 회원가입과 다중 사용자 권한 관리는 제공하지 않는다.
- 최초 계정은 서버 CLI 명령으로 생성하고 비밀번호는 대화형 입력으로 받는다.
  계정이 없을 때 웹에서 계정 생성을 개방하지 않고 초기 설정 안내만 보여준다.
- 비밀번호는 Argon2id로 해시한다. 서버 측 세션과 HttpOnly·SameSite 쿠키를 사용한다.
- 로그아웃과 세션 만료를 제공하며 로그인 시도에 제한을 둔다.
- 변경 요청에는 CSRF 보호를 적용하고 파일·뷰어·다운로드 API 모두 인증한다.
- 저장소 바깥 경로 접근, 상위 경로 탈출, 심볼릭 링크 접근을 차단한다.
- 업로드된 코드·HTML·스크립트를 실행하거나 앱 정적 파일로 제공하지 않는다.
- 콘텐츠 보안 정책과 응답 헤더로 업로드 콘텐츠의 스크립트 실행을 제한한다.
- 파일 이름, HTML 미리보기, 문서 내부 링크 등 사용자 콘텐츠를 신뢰하지 않는다.

## 화면 구성

- 로그인 후 파일 탐색기를 연다. 상단에는 경로·검색·업로드·폴더 생성 기능을 둔다.
- PC는 목록과 선택 파일 정보를 넓게 표시하고, 휴대폰은 한 열 목록과 터치 메뉴를 사용한다.
- 파일을 열면 문서·미디어 뷰어를 표시하고 닫으면 원래 폴더로 돌아간다.
- 업로드 진행, 빈 폴더, 로딩, 오류, 세션 만료 상태를 표시한다.
- 첫 버전은 한국어 UI를 기본으로 하고 모바일 브라우저 사용에 맞춘다.
- PWA 설치, 오프라인 파일 보관, 휴대폰 사진 자동 백업은 이번 범위에서 제외한다.

## 배포와 네트워크 전제

- 대상은 Docker와 Compose를 실행할 수 있는 일반적인 Linux 서버 또는 PC다.
  개발은 현재 환경에서 진행하되 특정 라우터·NAS 제품에 종속시키지 않는다.
- 서비스는 내부 주소와 지정 포트로 제공한다. Compose의 바인딩 주소·포트를 환경변수로 설정한다.
- 내부망 바인딩만으로 모든 환경의 외부 접근 차단을 보장하지 않는다.
  라우터 포트포워딩·UPnP·IPv6·호스트 방화벽 검증은 실제 배포 단계에서 수행한다.
- 라우터 VPN 설정·공인 도메인·인터넷 공개·인증서 자동 발급은 이번 범위에서 제외한다.
- HTTPS를 앞단에서 적용할 경우 Secure 쿠키 설정을 활성화할 수 있게 한다.
- 컨테이너는 비 root 사용자로 실행한다. 저장 폴더 권한 설정과 실행 방법을 README에 설명한다.

## 완료 판단과 검증

- Compose로 빌드·실행하고 개인 계정으로 로그인할 수 있다.
- 업로드한 파일의 다운로드 결과가 원본과 일치한다.
- 폴더·파일 생성·이름 변경·이동·삭제와 이름 충돌 처리가 동작한다.
- 인증 없는 파일 접근, 경로 탈출, 심볼릭 링크 접근과 CSRF 요청이 차단된다.
- 대표 PDF·DOCX·소스코드·이미지·동영상으로 미리보기를 확인한다.
- 동영상 Range 요청과 큰 파일 스트리밍을 확인한다.
- PC·휴대폰 화면에서 주요 흐름을 확인하고 컨테이너 재시작 후 데이터 유지를 검증한다.
- 환경에 Docker나 브라우저 실행 도구가 없으면 검증하지 못한 항목을 명시한다.

## 구현자에게 맡기는 사항

모듈·컴포넌트 분리, UI 색상·아이콘, 구체적인 API 경로, 페이지 크기,
미리보기 안전 상한, 테스트 도구와 세부 라이브러리 버전은 위 요구를 만족하도록 정한다.
기능 범위나 원본 파일 보존 방식을 바꾸는 결정은 사용자와 확인한다.
